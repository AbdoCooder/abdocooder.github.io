Webserv

HTTP/1.1 Server from scratch

Built a fully standards-compliant HTTP/1.1 web server in C++ without relying on any existing HTTP libraries. The core challenge was implementing a non-blocking event loop capable of serving hundreds of simultaneous connections without spawning a thread per client — requiring deep mastery of select()/poll() system calls, socket file descriptors, and the HTTP/1.1 RFC specification.

Architecture

Designed the full server architecture: configuration file parsing (NGINX-inspired syntax), virtual host routing, and request/response lifecycle. Led task distribution across a 3-person team.

Core Engine

Developed the central event loop using non-blocking I/O multiplexing. Each client connection is managed as a file descriptor in the event set — no blocking calls, no threads per connection.

Performance

Achieved +99% availability under Siege stress testing with over 200 concurrent connections sustained for 60 seconds — production-grade reliability for a from-scratch implementation.

02
Docker DevOps Infrastructure
March 2026

Inception

Docker Infrastructure & System Administration

Designed and deployed a production-style multi-container infrastructure entirely from scratch — no pre-built images allowed. Every container was built from Debian Bullseye or Alpine Linux base images with custom Dockerfiles, forcing a ground-up understanding of service configuration, networking, and security hardening at the container level.

Architecture

Eight containers (NGINX, WordPress, MariaDB, Redis, FTP, Adminer, Static Website, custom monitoring) communicating over an isolated bridge network. TLS termination at NGINX, PHP-FPM behind it. All services use named volumes with bind-mount drivers for data persistence.

Security Design

Zero hardcoded secrets — all credentials injected at runtime via Docker Secrets, mounted as files under /run/secrets/. Enforced automated crash recovery via process monitoring and compose restart policies, maintaining 100% uptime across all 8 containers.

Bonus Services

Extended the core stack with Redis object caching for WordPress, vsftpd FTP server for direct file transfer access, Adminer for web-based database management, a Python-generated static CV/portfolio page, and a custom monitoring service — all wired into the same isolated network.

C Systems Unix
2025

Minishell

Bash-inspired shell in C

Implemented a fully functional UNIX shell from scratch in C — the canonical systems programming challenge. The project demands correct handling of the process execution model, file descriptor inheritance across pipes, signal propagation, and lexer/parser design. Every feature that "just works" in Bash had to be manually implemented, from tokenization to heredoc handling.

Parsing & Execution

Built a lexer and parser to tokenize user input, handle quoting rules (single vs double quotes), expand environment variables ($VAR, $?), and construct an AST for command execution via execve() and fork()/waitpid().

Pipes & Redirections

Implemented full pipe chains (|) with correct file descriptor management using pipe() and dup2(). Supported all standard redirections: < (input), > (output), >> (append), and << (heredoc).

Built-ins & Signals

Hand-wrote all required built-in commands: cd, echo, pwd, export, unset, env, and exit. Implemented correct signal disposition for Ctrl-C, Ctrl-D, and Ctrl-\ in both interactive and non-interactive modes.

04
Java Distributed Backend
January 2026

Distributed Task Manager

Java Master-Slave Architecture

Designed and built a distributed computing framework in Java using a master-slave architecture across containerized nodes. The system distributes computation tasks to worker nodes, collects results, and handles node failures — a reduced but architecturally honest implementation of how real distributed systems like Hadoop MapReduce work.

Communication Protocol

Designed the binary message protocol from scratch — message format, task type enumeration, and framing rules — used by master, slave, and client nodes. All communication flows over raw TCP sockets, ensuring unambiguous, robust data exchange without a framework abstraction layer.

Master Node

Developed the orchestration layer: accepts task submissions from clients, distributes payloads (JAR files) to slave nodes dynamically, monitors execution, and aggregates results. Coordinated across 4 containerized nodes managed by Docker Compose.

Fault Tolerance

Implemented node failure detection via process monitoring and automatic recovery through compose restart policies. The system maintains correctness even when individual worker nodes go down mid-computation.
